# Habit 饮食日记阅读体验细化设计

日期：2026-08-10  
状态：设计已确认，等待用户复核书面规格

## 1. 目标

本轮在 Habit 0.5.0 饮食模块基础上完成三个聚焦调整：

1. 最近记录继续按日期从近到远分组，同一天内改为按发生时间从晚到早排列。
2. 最近记录与按日查看改为无外框双页签，支持点击和左右手势切换；记录卡强化“名称 → 类型”的阅读层级。
3. 饮品的冷热与冰量统一为一个可自由输入的“温度”字段，并让所有饮食照片支持点击放大预览。

本轮作为兼容性补丁发布为 Habit `0.5.1`，`versionCode = 11`。

## 2. 最近记录排序

- 日期组按 `recordEpochDay` 降序排列，最新日期在最上方。
- 同一日期内按 `occurredAt` 降序排列，最新一条记录在最上方。
- 发生时间相同时按记录 ID 降序排列，使新增记录的显示顺序稳定且符合“最新优先”。
- “按日查看”页面同步使用时间降序，避免两个入口对同一天记录采用相反顺序。
- 不修改数据库中的原始时间、创建时间或更新时间。

## 3. 双页签与左右滑动

顶部不再使用两个带底色的 `FilterChip`，改为：

- 两个等宽页签：“最近记录”“按日查看”。
- 标题水平居中，采用比正文高一级的字号和中等字重。
- 页签下方保留一条轻量分隔线，当前页签下方显示低饱和天蓝色指示线。
- 点击标题会切换页面，指示线平滑移动。
- 左右滑动内容页也会切换页面并同步标题与指示线。
- 切回按日查看时保留本次会话已经选择的日期。
- 页面使用同一个 Scaffold 顶部栏和悬浮新增按钮，不产生新的导航历史。

## 4. 记录卡阅读层级

每条饮食记录继续使用左图右文布局，左侧照片尺寸与圆角不变。右侧内容列在垂直方向整体居中，首要信息顺序固定为：

1. 名称。
2. 类型。
3. 时间与热量等次要信息。
4. “再记一次”“查看”操作。

### 4.1 名称规则

- 餐食：优先使用非空描述；描述为空时使用食物明细名称拼接；仍为空时显示“未命名餐食”。
- 饮品：优先使用饮品名称；饮品名称为空时使用非空描述；仍为空时显示“未命名饮品”。

### 4.2 类型规则

- 餐食显示餐次：早餐、午餐、晚餐、夜宵或加餐。
- 饮品显示当前饮品分类名称，例如咖啡、奶茶、自定义饮品分类。
- 饮品分类已删除或暂时无法解析时，回退到旧 `BeverageCategory` 对应中文名称；仍无法解析时显示“饮品”。
- 名称使用标题样式；类型和时间热量使用弱化颜色，避免与名称争夺层级。

整个记录卡仍可点击进入只读详情；缩略图点击优先打开照片预览，不触发卡片导航。

## 5. 温度字段统一

### 5.1 新记录与编辑

- 饮品编辑表单只显示一个“温度”自由文本输入框。
- 不提供预设选项、下拉菜单或选择 Chip。
- 用户可以输入“冷”“热”“常温”“正常冰”“少冰”等任意文本。
- 新保存记录把输入值写入现有 `temperature` 字段，并把 `iceLevel` 写为空字符串。
- 模板创建、模板套用和“再记一次”使用相同规则。

### 5.2 旧数据兼容

数据库和备份结构继续保留 `temperature` 与 `iceLevel` 两个字段，不删除列、不做破坏性迁移，以兼容旧版本本地数据和备份。

读取旧记录时生成统一温度文本：

- 两个字段都为空：显示为空。
- 只有一个字段非空：使用该字段。
- 两个字段相同：只显示一次。
- 两个字段不同：按“冷热 · 冰量”合并，例如“冷 · 少冰”。

编辑旧记录时，合并后的文本进入“温度”输入框。用户保存后写回 `temperature`，同时清空 `iceLevel`；在用户保存前，原始数据不被主动改写。

### 5.3 其他页面

- 只读详情只显示一行“温度”，不再分别显示冷热和冰量。
- 饮食模板编辑页只显示“温度”。
- 饮食统计将“冰量偏好”改为“温度偏好”，统计统一后的温度文本。
- 备份导出仍保留两个兼容字段；新记录的 `iceLevel` 为空。

## 6. 照片放大预览

新增可复用的饮食照片预览层：

- 最近记录和按日查看中的真实照片缩略图可点击预览。
- 只读饮食详情中的所有真实照片可点击预览。
- 编辑页中已添加的真实照片可点击预览，同时保留原有删除入口。
- 默认 Emoji、文件缺失或解码失败时不提供预览入口。
- 预览采用深色遮罩和尽可能大的 `ContentScale.Fit` 图片区域，不裁切照片。
- 支持系统返回键、右上角关闭按钮和点击遮罩关闭。
- 多张照片仍在详情页按现有顺序展示；每次预览用户点击的那一张。
- 本轮只提供放大查看，不加入手势缩放、旋转、保存或分享功能。

图片文件不存在或解码失败时立即关闭预览并回退原页面，不崩溃、不显示空白遮罩。

## 7. 数据流与组件边界

- `DietDiaryViewModel` 负责生成日期组、组内降序记录和饮品分类名称映射。
- `DietDiaryScreen` 使用页签与横向分页组件，只负责展示状态和派发交互。
- 提取纯函数生成记录卡名称、类型和统一温度文本，供列表、详情、编辑和统计共同使用。
- `DietPhotoPreviewDialog` 只接收可用照片文件和关闭回调，不读取数据库。
- 现有 `DietPhotoStore` 继续负责把相对路径解析为文件；数据库仍只保存相对路径。

## 8. 错误处理

- 分类名称暂不可用时使用旧枚举或“饮品”兜底，列表仍可阅读。
- 名称字段为空时使用明确的未命名文案，不显示空标题。
- 图片不存在或无法解码时继续显示默认 Emoji，预览入口不可点击。
- 横向分页与页签状态始终由同一选中索引同步，避免标题与内容不一致。
- 旧温度数据只在用户编辑并保存时归一化，不在启动时批量改写。

## 9. 验证范围

至少覆盖：

- 日期组降序、组内 `occurredAt` 与 ID 降序。
- 最近记录与按日查看通过点击和左右滑动切换，页签指示状态同步。
- 餐食名称、饮品名称、空名称兜底和类型中文显示。
- 自定义饮品分类在卡片中显示真实名称。
- 右侧信息列与照片区域垂直居中，名称位于类型上方。
- 新饮品表单只存在一个自由输入“温度”字段，不存在冰量输入。
- 旧冷热/冰量的四种合并情况，以及保存后 `iceLevel` 为空。
- 详情、模板、统计统一使用“温度”文案和数据。
- 有效照片可打开和关闭预览；默认 Emoji、缺失文件和损坏图片不打开预览且不崩溃。
- 旧数据库迁移和旧备份导入测试继续通过。
- 单元测试、Android UI 测试编译、Lint、Debug/Release APK 构建和模拟器安装。

## 10. 不在本轮范围

- 图片双指缩放、旋转、下载、分享或编辑。
- 饮食记录搜索、筛选或分页加载。
- 新增温度预设选项或自动补全。
- 删除数据库或备份中的旧 `iceLevel` 字段。
- 修改饮食照片的存储目录或压缩策略。

## 11. 验收标准

- 用户看到的顶部页签与已批准预览一致：无圆角格子、文字居中、底部指示线滑动。
- 最近日期和同日最新记录都最先出现。
- 所有记录卡第一行是名称、第二行是餐次或饮品分类，右侧内容视觉居中。
- 饮品编辑只需填写一个自由文本“温度”，旧冷热和冰量信息仍可读且不丢失。
- 点击任一有效饮食照片能够打开清晰的大图预览，并可可靠关闭。
- Habit 0.4.1、0.5.0 的现有本地数据与备份仍兼容。
- 新版 0.5.1 APK 使用现有稳定签名，可覆盖安装且不清除本地数据。
