# Habit 饮食总览、分类体系与界面细化设计

日期：2026-08-04  
状态：设计已确认，等待用户复核书面规格

## 1. 目标

本次迭代修正习惯与日历页面的布局细节，并完善饮食模块的信息架构。核心结果如下：

1. 新建习惯页面更充分地利用横向空间，底部操作区保留安全留白。
2. 习惯详情页的编辑、归档、删除操作保持统一的按钮结构。
3. 饮食记录拥有独立的只读详情页，查看与编辑不再混用。
4. 月历星期栏的上下间距统一。
5. 工作台最近七天准确表达每天完成的事项数量。
6. 饮食列表优先展示记录照片，没有照片时才显示默认 Emoji。
7. 饮食日记同时提供“最近记录”和“按日查看”两种视角。
8. 餐次新增“夜宵”，“正餐 / 加餐”统一改名为“餐食”。
9. 习惯、餐食、饮品分类均可新增、查看、重命名、隐藏、恢复和删除，预设分类不例外。
10. 全部页面的顶部左、右操作使用同一套轻量化视觉和点击区域。

本次迭代继续遵守北京时间（Asia/Shanghai）与旧版本本地数据兼容要求。

## 2. 已确认的产品边界

### 2.1 分类与餐次分离

- 习惯分类示例：学习、运动、生活。
- 餐食分类示例：家常菜、快餐、零食。
- 饮品分类示例：咖啡、奶茶、茶、果饮。
- 餐次是固定属性：早餐、午餐、晚餐、夜宵、加餐。

“夜宵”属于餐次，不属于餐食分类。餐次不进入分类管理页面。

### 2.2 饮食日记双视角

采用顶部双分段方案：

- `最近记录`：默认视角，按日期从近到远分组；同一天内按发生时间从早到晚排列。
- `按日查看`：保留现有七天时间轴和单日摘要，点击日期查看当天记录。

不采用独立二级总览页或下拉菜单切换，以避免入口隐藏和导航层级增加。

## 3. 视觉与交互规范

### 3.1 顶部操作统一

所有页面继续使用公共顶部栏组件：

- 左侧菜单与返回箭头使用相同尺寸的轻量点击区。
- 右侧 `＋` 使用与左侧操作一致的点击区、颜色和视觉重量。
- 右侧“编辑”使用普通操作文字字号，不得接近页面标题字号；点击区仍与其他顶部操作一致。
- 操作符号不增加显眼的圆形实底。
- 新增页面后应同时检查既有页面的顶部右侧操作，消除尺寸和对齐差异。

### 3.2 新建与编辑习惯

- 分类选择使用自动换行的横向流式布局，从左到右排列 FilterChip。
- 分类区域提供“＋ 新建”快捷入口，并可进入统一分类管理页。
- 底部保存按钮不直接贴住屏幕底边；按钮下方叠加导航栏安全区和额外视觉留白。
- 页面滚动内容应为底部保存区预留空间，最后一个字段不能被遮挡。

### 3.3 习惯详情

- 编辑习惯、归档习惯、删除习惯均采用带边框的全宽按钮。
- 删除按钮使用克制的危险色描边与文字，不使用无边框 TextButton。
- 原有二次删除确认流程保持不变。

### 3.4 月历星期栏

- 星期标题行与上方月份控制、下方日期网格分别保留一致的视觉间距。
- 星期文字与每列日期数字共用相同的七列网格宽度，保持垂直中心线对齐。
- 月份上一页、下一页继续使用大号轻量箭头，不增加圆形实底。
- 该规则应用于习惯详情月历以及其他复用的月历组件。

### 3.5 工作台最近七天

- 继续采用横向七日时间轴，不改成纵向列表。
- 七天按日期从早到晚排列，星期正常显示“一、二、三、四、五、六、日”，不使用“今天”替换星期。
- 不显示贯穿时间轴的横线，普通日期数字不使用圆形背景。
- 当天使用低饱和浅蓝轻描边圆角框，同时包住星期和日期数字；事项图标位于框外。
- 每个日期固定两个事项显示位，事项数量按完成的习惯记录计算，不对 Emoji 去重。
- 显示规则：
  - 0 项：不显示标识。
  - 1 项：显示第一个 Emoji。
  - 2 项：水平显示两个 Emoji。
  - 3 项及以上：显示第一个 Emoji 和 `+N`，其中 `N = 总事项数 - 1`。
  - 示例：3 项显示 `📚 +2`；10 项显示 `📚 +9`。
- 第一个 Emoji 按习惯排序顺序稳定选取，避免重组数据后随机变化。

## 4. 饮食模块页面设计

### 4.1 饮食日记列表

顶部结构为菜单、居中标题、右侧 `＋`，三者占用对称位置。

“最近记录”视角：

- 使用 LazyColumn 按日期分组。
- 日期组从最新日期到最早日期排列。
- 组内记录按 `occurredAt` 从早到晚排列，时间相同再按记录 ID 保持稳定顺序。
- 每条记录左侧优先显示排序第一张照片的方形圆角缩略图。
- 照片不存在、文件丢失或解码失败时，显示与记录类型匹配的默认 Emoji。
- 点击卡片或“查看”进入只读详情页；“再记一次”仍创建新记录草稿。

“按日查看”视角：

- 保留七天日期选择、当天摘要和当天列表。
- 视角切换仅改变页面内容，不产生新的导航历史。
- 返回饮食日记时保留本次会话中的视角选择和已选日期。

空状态分别说明“暂无饮食记录”和“所选日期暂无记录”，文案水平居中。

### 4.2 只读饮食详情

新增独立 `DietRecordDetail` 路由和页面：

- 顶部左侧返回，标题“饮食详情”，右侧小字号“编辑”。
- 页面只展示已保存且有内容的字段，不显示输入框、照片删除按钮、模板保存、类型切换等编辑控件。
- 按记录类型展示餐食或饮品信息；一次记录只展示其中一种结构。
- 展示发生日期和时间、餐次或饮品分类、描述、食物明细或饮品属性、热量、备注与照片。
- 多张照片按保存顺序展示。
- “再记一次”作为页面内容区操作保留。
- 右上角“编辑”进入现有编辑路由；保存后返回详情页并刷新数据。
- 记录不存在或已删除时显示轻量错误状态，并允许返回饮食日记。

### 4.3 记一餐与编辑饮食

- 顶部类型名称由“正餐 / 加餐”改为“餐食”。
- 餐食和饮品仍互斥，一次记录只能属于其中一种。
- 餐次展示顺序固定为：早餐、午餐、晚餐、夜宵、加餐。
- `MealType` 新增稳定枚举值 `LATE_NIGHT`；旧记录枚举值不变化。
- 餐食与饮品表单均增加主分类选择；主分类单选且必选。
- 分类 Chip 横向自动换行，并提供“＋ 新建”和“管理分类”入口。
- 快速新增分类成功后自动选中新增项，返回编辑页时不丢失其他已填写内容。

## 5. 统一分类管理

### 5.1 页面结构

统一分类管理页使用顶部分段：习惯、餐食、饮品。

每个分段均支持：

- 查看全部分类及使用数量。
- 新建分类。
- 重命名分类。
- 隐藏与恢复分类。
- 删除分类。
- 编辑预设分类；预设分类不再只有隐藏权限。

分类管理页可从侧边栏、设置页及各新增/编辑页面进入。返回时保持来源语义，不额外叠加错误的工作台历史页面。

### 5.2 删除和迁移规则

- 未被使用的分类可确认后直接删除。
- 已被习惯、饮食记录或饮食模板使用的分类，删除前必须选择同类型迁移目标。
- 迁移目标不得是自身、隐藏分类或其他类型分类。
- 迁移与删除在同一数据库事务中完成，失败时不产生部分迁移。
- 不允许删除某一类型最后一个可用分类；应先创建替代分类。
- 编辑旧记录时，即使其当前分类已隐藏，也要显示当前分类，用户可主动改选。

## 6. 数据模型与旧数据迁移

### 6.1 数据表策略

保留现有习惯 `categories` 表和 `categoryId` 关系，降低对稳定习惯数据的迁移风险。

新增饮食分类表 `diet_categories`：

- `id`
- `scope`：`MEAL` 或 `BEVERAGE`
- `name`
- `isPreset`
- `isHidden`
- `sortOrder`
- `createdAt`
- `updatedAt`

为饮食记录和饮食模板增加稳定的 `dietCategoryId`。分类 ID 是记录归属依据，重命名不会改写历史记录。

界面层通过统一的分类管理协调器组合习惯分类仓库与饮食分类仓库，因此用户看到统一页面，底层仍保持边界清晰。

### 6.2 迁移规则

Room 数据库升级必须提供显式迁移，不允许 destructive migration：

- 创建餐食预设分类，包括“家常菜、快餐、零食、其他餐食”。
- 创建饮品预设分类，包括“咖啡、奶茶、茶、果饮、乳饮、其他饮品”。
- 旧餐食记录和模板迁移到“其他餐食”。
- 旧饮品记录依据原 `BeverageCategory` 值迁移到对应饮品分类；未知值迁移到“其他饮品”。
- 原记录 ID、发生时间、创建时间、更新时间、照片关系和模板关系保持不变。
- 备份导入支持旧结构：缺少饮食分类字段时应用同一映射规则。
- 新版导出包含饮食分类定义与记录分类引用。
- 合并导入发生分类冲突时，沿用既有“新数据优先”规则，并保证引用最终指向有效分类。

## 7. 组件与数据流边界

新增或调整的独立单元：

- `HabitTopAppBar`：统一左、右顶部操作槽位。
- `RecentWeekTimeline`：只负责七日布局与两个显示位规则。
- `DietDiaryModeSelector`：管理最近记录与按日查看的视角切换。
- `DietRecordThumbnail`：负责照片缩略图与 Emoji 降级。
- `DietRecordDetailScreen/ViewModel`：只读详情状态与导航。
- `CategoryChipFlow`：复用横向自动换行的分类选择。
- `DietCategoryRepository`：饮食分类 CRUD、可见列表和迁移删除。
- `UnifiedCategoryViewModel`：组合三类分类数据供统一管理页使用。

页面不直接访问 DAO；数据写入通过仓库事务完成。照片文件解析继续通过现有 `DietPhotoStore`，数据库只保存相对路径。

## 8. 错误处理

- 缩略图文件丢失或解码失败不阻断列表，立即回退默认 Emoji。
- 快速新增分类遇到重名时保留表单内容并显示明确提示。
- 分类删除迁移失败时保留源分类和全部引用。
- 只读详情加载不到记录时显示错误状态，不跳入空编辑页。
- 饮食总览加载为空时显示居中空状态。
- 任何数据库迁移异常不得自动清空本地数据库。

## 9. 验证范围

本项目为前期小型 App，验证保持与风险相称，不进行无关的大规模检查。

至少覆盖：

- 分类 Chip 流式布局和保存按钮底部安全间距的 Compose UI 测试。
- 习惯详情三个按钮均为描边按钮。
- 月历星期栏与日期列对齐的组件测试。
- 最近七天 0、1、2、3、10 个事项的显示规则，并验证相同 Emoji 的不同习惯不会被去重。
- 饮食总览的日期倒序、组内时间升序。
- 有照片、无照片、照片损坏三种缩略图状态。
- 点击查看进入只读详情，点击编辑才进入编辑页。
- 餐食/饮品互斥、夜宵顺序和旧餐次兼容。
- 三类分类的新增、重命名、隐藏、恢复、删除与迁移事务。
- Room 旧版本数据库升级后习惯、打卡、饮食、照片、模板数据仍存在。
- 旧备份和新版备份导入兼容。
- 单元测试、Lint、Android 测试编译和 Debug APK 构建。

## 10. 不在本次范围

- 自定义餐次及餐次增删改查。
- 多分类或多标签记录；每条习惯、餐食、饮品仍只有一个主分类。
- 云同步、多人共享或后台分类管理。
- AI 自动识图、自动分类或热量估算扩展。
- 改变现有应用主导航结构或重新加入底部导航。

## 11. 验收标准

- 九项用户反馈均可在实际设备上复现为已修正状态。
- 新增或明显修改的页面与已确认 UI 预览一致。
- 顶部操作在所有页面视觉一致，饮食详情“编辑”不抢占标题层级。
- 工作台七日区域保持横向布局，当天圆角框和事项计数严格符合确认规则。
- 0.4.1 及更早版本的有效本地数据升级后仍可读取。
- 新版 Debug APK 可在当前签名一致的安装链路上覆盖安装。
