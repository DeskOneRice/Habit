# Habit 0.2.2 日期列对齐与系统栏可读性修复设计

日期：2026-08-03  
目标版本：`versionCode = 4`，`versionName = "0.2.2"`

## 目标

修复新建习惯日期选择器中星期标题与日期数字未按同一列居中的问题，并确保近白主题下状态栏和底部导航栏内容清晰可见。此次仅做视觉与系统栏修复，不引入饮食数据模型或改变现有业务流程。

## 根因

### 日期列

星期标题当前是七个带 `weight(1f)` 的 `Text`，文本使用默认起始对齐；日期则是七个等宽 `TextButton`，按钮内容默认居中。两行虽然都分成七列，但列内对齐规则不同，因此星期文字与日期数字视觉错位。

### 系统栏

应用使用浅色主题，但没有显式同步系统栏背景色和图标明暗模式。HyperOS 可能保留白色状态栏图标，使其与近白背景之间缺少对比度。

## 设计

### 统一日期网格单元

- 星期标题和日期都使用相同的七等分单元容器。
- 每个单元填满自己的列宽，并在水平、垂直方向居中内容。
- 保持星期顺序为周一至周日：`一、二、三、四、五、六、日`。
- 日期点击区域、选中圆形背景、月份切换和现有日期计算逻辑不变。
- 抽取一个可测试的对齐策略常量或网格单元组件，避免星期标题与日期再次使用不同的列内对齐规则。

### 浅色系统栏

- 系统状态栏背景色跟随当前 `MaterialTheme.colorScheme.background`。
- 底部导航栏背景色同样跟随主题背景色。
- 当前五套内置主题均属于浅色主题，因此状态栏和导航栏统一使用深色图标。
- 主题切换后，系统栏颜色在同一界面会话中同步更新。
- 不改变现有窗口内容区域和安全区处理，避免页面整体上下偏移。

## 兼容性

- Room 数据库结构和 schema version 保持不变。
- DataStore 键和备份 JSON schema 保持不变。
- 不使用 `fallbackToDestructiveMigration`。
- APK 必须沿用第一版证书签名，可直接覆盖安装并保留本地数据。

## 测试与验收

- 单元测试验证星期顺序及统一居中对齐策略。
- Compose 测试验证七个星期标题和对应日期使用相同列中心。
- 系统栏策略测试验证五套浅色主题都请求深色状态栏与导航栏图标。
- 运行完整 JVM 测试并编译 Android 测试源码。
- 生成 0.2.2 APK，验证包名、版本、ZIP 对齐和证书 SHA-256。
- Redmi K70 人工验收：星期文字正对下方日期列中心；白色或近白背景下，时间、信号、电量和底部手势区域清晰可见。

## 后续范围

饮食记录作为独立功能规格在 0.2.2 修复完成后设计。首轮讨论将在“快速文字记录”“结构化餐次记录”“含图片与 AI 分析”三种范围中选择，不在本次修复中预埋未经确认的数据表或入口。
