# Habit Android MVP 设计规格

日期：2026-07-29  
状态：已完成对话评审，等待书面规格最终确认

## 1. 产品目标

Habit 是一款面向学生的轻量习惯记录 Android 应用。产品通过月历、习惯图标和每日打卡形成仪式感，让用户直观看到习惯积累。

本阶段目标是在两天内交付一个可在 Redmi K70（Xiaomi HyperOS 3.0）上侧载使用的离线 MVP。MVP 聚焦习惯创建、分类、每日打卡、历史补签、整体月历、单习惯月历和基础统计。

## 2. MVP 范围

### 2.1 包含

- 创建、编辑、归档和删除习惯。
- 从内置 Emoji 图标库选择习惯图标。
- 为习惯选择主题色。
- 使用预设分类，并创建、重命名和删除自定义分类。
- 每个启用习惯每天可完成一次打卡。
- 支持今天打卡以及任意历史日期的补签和取消。
- 月历优先的整体日历首页。
- 每个日期格直接展示已完成习惯的专属 Emoji 图标。
- 单习惯日历与累计完成、当前连续和最长连续统计。
- 五套内置主题色，并支持在设置页即时切换。
- Room 本地持久化。
- 可安装的 Android 调试 APK 和简短安装说明。

### 2.2 不包含

- 用户登录和账号系统。
- 云端同步、后台管理系统和跨设备使用。
- 打卡提醒或本地通知。
- 饮食记录、热量估算和饮品记录。
- AI 对话、习惯分析和报告生成。
- 支付、订阅和应用商店上架。
- iOS 客户端。

这些能力属于后续版本，不影响当前核心模块的接口边界。

## 3. 目标平台与技术路线

- 平台：Android。
- 主要验证设备：Redmi K70，Xiaomi HyperOS 3.0，3200×1440。
- UI：Kotlin + Jetpack Compose。
- 状态管理：ViewModel + 单向数据流。
- 本地数据库：Room。
- 轻量偏好存储：Android DataStore。
- 架构：按功能模块组织的 MVVM，Repository 作为业务和数据边界。
- 网络：MVP 不访问网络，不申请网络权限。

选择原生 Android 是因为当前只交付 Android，原生方案在系统适配、本地数据库、月历交互和后续维护方面风险最低。

## 4. 页面与导航

应用使用三个底部导航入口。

### 4.1 日历

日历是默认首页，采用“月历优先”布局：

- 顶部显示当前月份、当月坚持天数和当月完成率。
- 月历格子显示日期和当天已完成习惯的 Emoji 图标。
- 一个日期格最多展示四个图标，更多记录显示为“+N”。
- 图标按习惯创建顺序排列。
- 点击任意非未来日期，在月历下方打开当天适用的习惯列表。
- 用户可在当天习惯列表中打卡或取消打卡。
- 未来日期可以查看，但所有打卡控件禁用。

### 4.2 习惯

- 按分类展示启用中的习惯。
- 提供创建习惯入口。
- 习惯行显示图标、名称、分类、主题色和当天状态。
- 点击习惯进入详情页。
- 详情页展示单习惯月历、累计完成次数、当前连续天数和最长连续天数。
- 编辑页支持修改名称、图标、主题色和分类。
- 支持归档和删除。

### 4.3 设置

- 管理自定义分类。
- 隐藏或恢复预设分类。
- 在“外观”中切换内置主题色。
- 查看“数据仅保存在本机，卸载会清除数据”的说明。
- 显示应用版本。

### 4.4 首次使用

1. 展示简短欢迎页，说明产品用途和本地数据策略。
2. 引导用户创建第一个习惯。
3. 用户填写名称，并选择分类、Emoji 图标和主题色。
4. 创建成功后进入日历首页。

## 5. 业务规则

### 5.1 习惯

每个习惯包含：

- 名称，长度 1～30 个字符，不允许全为空白。
- 内置 Emoji 图标标识。
- 主题色。
- 所属分类。
- 业务开始日期。
- 精确创建时间和最后更新时间。
- 启用或归档状态。
- 稳定的创建顺序。

允许习惯重名，用户通过图标和分类区分。新习惯从创建当天开始参与待打卡和统计，不要求填写创建前的记录。

归档保留历史数据，但习惯从归档当天起不再参与新的待打卡和应打卡次数。归档前的适用日期仍可查看和修改。删除习惯会级联删除其全部打卡记录，执行前必须二次确认。

### 5.2 打卡

- 同一习惯同一业务日期只能有一个有效打卡记录。
- 点击未完成项会创建打卡；点击已完成项会取消打卡。
- 用户可以修改今天及任意过去的适用日期。
- 适用日期必须不早于习惯开始日期；若习惯已归档，还必须早于归档生效日期。
- 未来日期不能创建或取消打卡。
- 快速连续点击不会产生重复记录。
- 补签归属于用户指定的业务日期，而不是实际操作日期。

### 5.3 分类

应用预设以下分类：

- 学习
- 运动
- 生活
- 健康
- 其他

用户可以新增和重命名自定义分类。预设分类可以隐藏，但不删除。删除包含习惯的自定义分类前，用户必须选择目标分类完成迁移；迁移和删除在一个数据库事务中完成。

### 5.4 统计

- 累计完成次数：该习惯所有有效打卡日期数量。
- 当前连续天数：若今天已完成，则从今天向前连续计算；若今天尚未完成，则从昨天向前连续计算。
- 最长连续天数：该习惯历史上最长的连续完成日期区间。
- 当月应打卡次数：逐日统计当日处于启用状态且已开始的习惯数量。
- 当月完成率：当月有效完成次数除以当月应打卡次数；分母为零时显示为 0%，不显示 NaN 或无穷值。
- 当月坚持天数：当月至少完成一个习惯的不同日期数量。

## 6. 日期与时间模型

业务日期和数据库审计时间严格分离。

### 6.1 业务日期

- `checkInDate`：打卡归属日期，数据库使用 `epochDay` 整数保存。
- `habitStartDate`：习惯开始参与打卡和统计的日期，使用 `epochDay` 保存。
- `archivedDate`：习惯停止参与新待办和统计的日期；未归档时为空。

业务日期按手机当前本地日历解释，不包含时刻或时区。连续天数、月历位置和完成率只使用业务日期字段。

### 6.2 审计时间

- `createdAt`：记录首次持久化的精确时刻。
- `updatedAt`：记录最后修改的精确时刻。

审计时间以 UTC Unix 毫秒值保存。界面展示时转换为手机本地时间。

例如，用户在 7 月 30 日补签 7 月 28 日：

- `checkInDate` 为 7 月 28 日对应的 `epochDay`。
- `createdAt` 为 7 月 30 日实际操作时刻的 UTC 时间戳。
- 统计和日历均把该记录归入 7 月 28 日。

数据库不保存“今天”“星期三”“7月29日”等展示字符串。界面根据业务日期和当前区域设置动态生成中文文案。

## 7. 数据模型

### 7.1 Category

- `id`
- `name`
- `isPreset`
- `isHidden`
- `sortOrder`
- `createdAt`
- `updatedAt`

### 7.2 Habit

- `id`
- `name`
- `iconKey`
- `themeColor`
- `categoryId`
- `startEpochDay`
- `archivedEpochDay`，可空
- `sortOrder`
- `createdAt`
- `updatedAt`

### 7.3 CheckIn

- `id`
- `habitId`
- `checkInEpochDay`
- `createdAt`
- `updatedAt`

`CheckIn` 对 `(habitId, checkInEpochDay)` 建立唯一索引。`Habit.categoryId` 引用 `Category.id`。删除习惯时级联删除打卡；分类不使用级联删除，必须先迁移习惯。

## 8. 架构与模块边界

```text
Jetpack Compose UI
        ↓ 用户事件 / UI 状态
ViewModel
        ↓ 用例调用 / StateFlow
Repository
        ↓ 事务、统计、数据映射
Room DAO
        ↓
SQLite
```

### 8.1 Calendar 模块

负责整体月历、选中日期、每日打卡列表、图标聚合和月度统计。它依赖 Repository 提供按月和按日的只读数据流，不直接访问 DAO。

### 8.2 Habits 模块

负责习惯列表、创建编辑、归档删除、单习惯日历和单习惯统计。

### 8.3 Categories 模块

负责预设分类初始化、自定义分类管理、隐藏预设分类和分类迁移事务。

### 8.4 Settings 模块

负责本地数据说明、应用版本和轻量界面设置。

### 8.5 Core Data 模块

包含 Room 实体、DAO、数据库、Repository 实现、日期转换、统计算法和数据库版本迁移。

每个界面通过 ViewModel 暴露不可变 UI 状态，通过显式事件方法执行操作。Room 的 `Flow` 在数据变化后驱动日历、列表和统计自动刷新。

### 8.6 Theme 模块

负责内置主题定义、当前主题状态和 DataStore 持久化。主题使用稳定标识保存，而不是直接保存颜色值：

- `SKY_BLUE`：低饱和天蓝，默认主题。
- `SOFT_PINK`：柔粉。
- `SAGE_GREEN`：鼠尾草绿。
- `MIST_PURPLE`：雾紫。
- `NEUTRAL_GRAY`：中性灰。

设置页点击主题后立即更新全局 Compose Theme，并异步写入 DataStore，无需额外保存按钮。应用启动时先使用默认天蓝主题，再读取 DataStore 恢复上次选择；读取失败或标识无法识别时回退到 `SKY_BLUE`。主题设置故障不得影响 Room 中的习惯和打卡数据。

## 9. 错误处理与一致性

- 表单在本地同步校验，错误显示在对应字段附近。
- 未来日期的打卡操作在 UI 和 Repository 两层拒绝。
- 打卡写入使用唯一索引和事务防止重复。
- 分类迁移与分类删除在同一事务中完成。
- 数据库操作失败时保留当前页面状态，并显示可理解的短提示。
- DataStore 读取失败时回退到默认天蓝主题；写入失败时保留当前会话中的选择，并提示设置可能无法在重启后保留。
- 删除习惯和分类迁移前显示二次确认对话框。
- 应用进程退出不会清除已提交事务。
- Room 数据库从版本 1 开始，后续结构修改必须提供显式迁移。

## 10. 视觉方向

- 整体风格：简洁、轻盈、偏 Ins 风。
- 默认采用中性白背景、低饱和天蓝主强调色和柔和阴影。
- 信息层级以月历为第一视觉焦点。
- 每个习惯由 Emoji 和主题色共同识别。
- 习惯主题色属于单个习惯的识别属性，不随应用全局主题切换而改变。
- 用户可切换低饱和天蓝、柔粉、鼠尾草绿、雾紫和中性灰五套内置主题。
- 主题只改变按钮、选中态、打卡状态、进度条、链接和浅色强调卡片。
- 页面背景保持中性白，正文保持深灰，Emoji 保持原色。
- 卡片圆角适中，避免过度装饰。
- 所有文本和交互元素适配系统字体缩放。
- 布局按可用宽度自适应，不依赖 Redmi K70 的固定像素尺寸。

## 11. 测试策略

### 11.1 单元测试

- `epochDay` 与显示日期转换。
- 跨月、跨年和闰年。
- 今天、昨天和未来日期判定。
- 当前连续天数和最长连续天数。
- 月应打卡次数、完成次数、坚持天数和完成率。
- 归档日期对统计分母的影响。
- 图标排序和“+N”聚合。
- 主题标识映射、未知主题回退和默认主题逻辑。

### 11.2 数据存储测试

- 习惯、分类和打卡的增删改查。
- 同一习惯同一天的唯一约束。
- 删除习惯级联删除打卡。
- 分类迁移事务的原子性。
- Flow 在数据变化后发出新结果。
- DataStore 正确保存和恢复主题标识。

### 11.3 UI 测试

- 首次使用和创建第一个习惯。
- 创建、编辑、归档和删除习惯。
- 今天打卡、取消和历史补签。
- 未来日期控件禁用。
- 整体日历与单习惯日历数据一致。
- 空状态、长名称和四个以上图标。
- 五套主题即时切换，且应用重启后恢复上次主题。
- 各主题下正文、按钮、选中态和禁用态具有清晰可读的对比度。

### 11.4 设备验证

- 生成可安装的调试 APK。
- 在 Redmi K70 / Xiaomi HyperOS 3.0 上安装和启动。
- 验证创建、打卡、补签、双日历、统计和重启持久化。
- 确认主要界面无明显溢出、遮挡或不可点击区域。

## 12. 交付与验收

MVP 完成时应提供：

- Android 项目源代码。
- 可侧载安装的调试 APK。
- 简短安装说明和核心功能使用说明。
- 自动化测试结果。

验收条件：

1. Redmi K70 可以安装并启动 APK。
2. 用户能够创建带分类、图标和主题色的习惯。
3. 用户能够完成今天打卡和任意历史日期补签或取消。
4. 整体月历正确显示各习惯图标及“+N”。
5. 单习惯月历和三项基础统计正确。
6. 分类管理、归档和删除流程可用且有必要确认。
7. 应用重启后数据仍然存在。
8. 主要流程没有阻断性崩溃或明显数据错误。
9. 用户可以切换五套内置主题，且重启后仍保持选择。

## 13. 后续扩展顺序

MVP 稳定后，建议按以下顺序扩展：

1. 本地提醒。
2. 数据导出与备份。
3. 登录和云同步。
4. 饮食记录模块。
5. AI 习惯分析、对话和周期报告。
6. 管理后台、支付和应用商店发布。
