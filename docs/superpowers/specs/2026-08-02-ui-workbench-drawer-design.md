# Habit 0.2 UI 工作台与侧滑菜单设计规格

日期：2026-08-02
状态：用户已确认设计方向，等待书面规格复核
目标版本：`versionCode = 2`，`versionName = "0.2.0"`

## 1. 背景与目标

Habit 0.1 的功能和本地数据在 Redmi K70 真机测试中工作正常，但界面偏系统默认风格，底部导航视觉不符合预期，习惯图标只有 6 个候选。0.2 的目标是在不扩大业务功能范围、不丢失旧版本本地数据的前提下完成一次聚焦的 UI 改版：

- 取消底部导航，改为纯侧滑抽屉菜单；
- 增加“今日工作台”作为默认首页；
- 统一低饱和、简洁、轻量的视觉语言；
- 将 Emoji 选择器升级为分类、搜索、自定义和最近使用；
- 保留 0.1 的习惯、分类、打卡、日期语义和主题数据；
- 不增加联网权限、饮食记录、AI 报告或占位入口。

## 2. 已确认的产品决策

### 2.1 导航方向

采用纯侧滑菜单，不显示底部导航栏。抽屉同时支持：

- 从屏幕左边缘右滑打开；
- 点击一级页面左上角菜单按钮打开；
- 点击遮罩、向左滑或按系统返回键关闭；
- 点击菜单项后自动关闭并导航；
- 当前菜单项使用当前主题色的低饱和浅色背景标识。

一级页面固定为：

1. 今日工作台；
2. 习惯日历；
3. 我的习惯；
4. 分类管理；
5. 主题与设置。

抽屉顶部显示 Habit 标识、短句“积累看得见的日常”和当天完成进度。饮食记录与习惯报告不在本版本出现。

### 2.2 默认首页

首次引导完成后和普通冷启动后均进入“今日工作台”。工作台展示现有本地数据的聚合视图，不创建新的业务数据类型。

### 2.3 Emoji 方向

采用 60–80 个内置候选，提供分类、中文搜索、自定义 Emoji 输入和最近使用。现有 6 个图标键值继续兼容。

### 2.4 改版边界

本版本只重做现有功能及其入口，不加入饮食、AI、报告或后台管理功能，也不显示“即将推出”的空入口。

## 3. 信息架构与导航行为

### 3.1 路由

新增顶级路由 `workbench`。保留 `calendar`、`habits`、`categories`、`settings`、`habit_detail/{habitId}` 和 `habit_editor`。

`welcome` 仍只用于首次启动。首次创建习惯完成后，清除欢迎页和编辑页返回栈并进入 `workbench`。

### 3.2 一级与二级页面

- `workbench`、`calendar`、`habits`、`categories`、`settings` 属于一级页面，显示菜单按钮并由同一个抽屉容器承载。
- `habit_detail`、`habit_editor` 属于二级页面，显示返回按钮，不显示抽屉按钮。
- 工作台处于根页面时，系统返回键退出应用。
- 抽屉打开时，系统返回键优先关闭抽屉。
- 二级页面返回时恢复来源页面及其滚动/选择状态。

### 3.3 Compose 结构

应用壳使用 Material 3 `ModalNavigationDrawer` 包裹顶级 `NavHost`。抽屉手势只在一级页面开启，避免与二级编辑页面、横向控件或系统返回手势冲突。

导航列表、当前路由判断、标题和图标由单一 `DrawerDestination` 定义提供，避免页面和抽屉分别维护重复映射。

## 4. 今日工作台

### 4.1 页面层级

从上到下固定为：

1. 顶部栏：菜单按钮、标题/日期、新建习惯按钮；
2. 今日进度卡：完成数、总数、百分比，以及今日活动习惯中的最长当前连续天数；
3. 今日习惯列表：Emoji、名称、分类/连续天数、圆形打卡按钮；
4. 最近 7 天迷你日历：每天显示最多 3 个不同习惯 Emoji，超出时显示 `+N`；不得用同一个通用圆点替代不同习惯标记；
5. 本月数据：活跃天数、完成率、最长连续天数；
6. 空状态：简洁 Emoji、说明文字和“新建习惯”按钮。

### 4.2 交互

- 点击习惯行进入详情；
- 点击圆形按钮直接切换今天的打卡状态；
- 打卡进行中只禁用对应习惯按钮，不冻结整页；
- 点击 7 天区域或“打开月历”进入完整日历；
- 点击右上角新增按钮进入习惯编辑页；
- 成功打卡使用短促缩放/颜色过渡，并由数据库结果驱动最终状态。

### 4.3 数据流

新增 `WorkbenchViewModel`，只组合现有 repository 的可观察数据：活动习惯、当天打卡、最近 7 天日历快照和本月统计。业务校验仍由现有 repository 执行，工作台不复制日期限制、打卡切换或连续天数算法。

所有数据来自本地 Room 与 DataStore，不增加网络请求。设备日期变化时复用现有 `DeviceDateProvider` 和刷新机制。

## 5. 视觉系统

### 5.1 基础风格

- 页面背景使用极浅蓝灰色；
- 内容卡片使用白色或接近白色的中性表面；
- 当前主题色只用于主按钮、选中态、进度和轻量强调；
- 低饱和天蓝继续作为默认主题；
- 卡片圆角统一为 16–20dp；
- 阴影仅用于抽屉、底部弹层和少量重点卡片；
- 正文使用深灰，不使用大面积纯黑；
- 图标统一为 Material 线性图标；
- 点击区域不小于 48dp。

主题切换继续保留。更换主题时改变强调色、浅色选中背景和进度色，内容表面保持中性，不把整个页面染成主题色。

### 5.2 页面组件

建立可复用组件：

- `HabitTopAppBar`：一级菜单/二级返回两种模式；
- `HabitDrawerContent`：品牌、今日进度和导航项；
- `HabitCard`：统一圆角、内边距和中性表面；
- `HabitCheckRow`：Emoji 色块、文字信息和打卡按钮；
- `HabitProgressCard`：完成数和环形进度；
- `RecentWeekStrip`：最近 7 天与 Emoji 标记；
- `HabitEmptyState`：一致的空状态布局；
- `HabitEmoji`：全应用统一渲染旧图标键和新 Unicode Emoji。

### 5.3 动画与系统区域

抽屉、打卡和卡片状态使用 150–250ms 的柔和过渡，并尊重系统“减少动画”设置。布局必须正确处理状态栏、手势导航底部安全区、字体缩放和 Redmi K70 的 3200×1440 分辨率。

## 6. Emoji 选择器

### 6.1 候选与分类

内置目录包含 60–80 个 Emoji，分类为：

- 最近；
- 学习；
- 运动；
- 生活；
- 饮食；
- 健康；
- 兴趣。

每个候选包含稳定标识、Unicode Emoji、中文名称和搜索关键词。搜索忽略首尾空格，并匹配名称、关键词和分类。

### 6.2 交互

在习惯编辑页点击当前图标，打开 Material 3 底部弹层。弹层包含搜索框、横向分类、6 列候选网格和“使用手机键盘输入自定义 Emoji”入口。

选择后立即更新编辑草稿并关闭弹层。最近使用最多保留 12 个，按最近选择顺序去重。

### 6.3 自定义输入校验

自定义输入去除首尾空白后必须是一个可显示的 Emoji grapheme，不接受空值、纯字母、数字、汉字或多个无关字符。校验失败时在输入框下显示就地提示并保留原输入，不关闭弹层。

### 6.4 存储格式与旧值兼容

现有数据库字段 `iconKey` 为文本字段，因此不新增列、不改变 Room schema：

- 旧值 `book`、`sprout`、`run`、`heart`、`water`、`star` 继续由兼容映射渲染；
- 新内置或自定义值使用 `emoji:<Unicode grapheme>` 格式；
- 未识别的旧值使用安全默认图标，但不覆写数据库原值。

最近使用列表作为新的 DataStore preference 保存，默认空列表，最多 12 项。该偏好是附加字段，不影响现有主题偏好。

## 7. 旧版本本地数据兼容

### 7.1 必须保持不变

- `applicationId` 保持 `com.habit.app`；
- 使用与 0.1 APK 相同的签名密钥构建可升级 APK；
- Room 数据库名称保持不变；
- Room schema 版本保持 `1`，因为本次不增加或修改表、列、索引与约束；
- 不使用 `fallbackToDestructiveMigration`；
- 不清除应用数据，不更改数据库文件位置；
- 现有日期字段、`createTime` 审计字段和设备日期语义不变；
- 主题 preference 的 key 与含义不变。

### 7.2 版本升级

0.2 设置 `versionCode = 2`、`versionName = "0.2.0"`。安装验证必须使用 `adb install -r` 或系统安装器覆盖安装，不得先卸载 0.1。

### 7.3 升级验收数据集

在 0.1 中预先创建：

- 至少两个分类；
- 至少三个习惯，覆盖不同旧 Emoji 和主题色；
- 至少七天打卡历史；
- 一个已归档习惯；
- 非默认应用主题。

覆盖安装 0.2 后必须确认：

- 所有习惯、分类、归档状态与排序不变；
- 所有历史打卡日期、统计和日历 Emoji 正确；
- 旧 Emoji 正确显示；
- 主题设置保留；
- 新工作台立即读取旧数据；
- 编辑旧习惯并改用新 Emoji 后，其他字段不变；
- 应用进程重启后数据仍一致。

## 8. 错误处理与状态恢复

- 工作台首次加载失败时显示可重试状态，不显示错误的零数据；
- 单个习惯打卡失败时恢复原状态并显示明确消息；
- 保存习惯失败时保留名称、分类、颜色和 Emoji 草稿；
- Emoji 搜索无结果时显示“没有匹配图标”及自定义入口；
- 数据库中出现未知 `iconKey` 时安全显示默认 Emoji，不崩溃、不修改原值；
- 抽屉关闭、旋转或 Activity 重建后恢复当前路由，不错误跳回欢迎页。

## 9. 无障碍与适配

- 菜单按钮、返回按钮、打卡按钮、Emoji 候选和主题选项均有明确 content description；
- 当前菜单项、当前 Emoji 和当前主题暴露 selected 状态；
- 抽屉打开后焦点进入抽屉，关闭后返回触发按钮；
- 触控区域不小于 48dp；
- 文字在系统字体放大时不截断关键操作；
- 颜色不是唯一状态表达，打卡和选中态同时使用形状/图标/语义；
- 支持系统返回手势和屏幕阅读器。

## 10. 测试与验收

### 10.1 单元测试

- 工作台状态聚合、百分比和日期切换；
- Emoji 分类、中文搜索、去重最近使用；
- 旧键值与新 `emoji:` 值渲染；
- 自定义 Emoji 校验；
- 失败状态恢复。

### 10.2 Android 设备测试

- 首次引导完成后进入工作台；
- 菜单按钮、边缘手势、遮罩和返回键的抽屉行为；
- 五个一级页面导航且无底部导航；
- 工作台从旧数据展示进度并可直接打卡；
- 最近 7 天显示不同习惯 Emoji；
- Emoji 分类、搜索、自定义输入和最近使用；
- 主题切换后中性表面与强调色正确；
- 二级页面返回栈正确；
- Redmi K70 尺寸、状态栏、手势导航和横竖屏重建不崩溃。

### 10.3 升级测试

必须保留由 0.1 正式 APK 创建的数据，使用相同签名的 0.2 APK 覆盖安装并执行第 7.3 节全部检查。模拟器通过后，再在 Redmi K70 上用真实现有数据执行一次覆盖安装与人工验收。

### 10.4 完整门禁

实现完成后必须通过：

- 全部既有单元测试；
- 全部既有 60 项设备测试；
- 本规格新增的单元与设备测试；
- `lintDebug` 无错误；
- `assembleDebug` 成功；
- 最终 APK 新装、冷启动和覆盖升级均成功；
- Git 工作树干净，交付 APK 哈希记录在交付说明中。

## 11. 非目标

本次不实现：

- 饮食与热量记录；
- AI 对话与报告；
- 登录、同步或后台管理的新能力；
- 联网、云备份或第三方服务；
- 新数据库实体；
- 自定义主题编辑器；
- “即将推出”占位页面。

## 12. Git 与实施顺序

设计规格在分支 `codex/ui-workbench-drawer` 上单独提交，作为改版前检查点。用户书面复核通过后，再编写实施计划；正式代码修改只能发生在该规格提交之后。
