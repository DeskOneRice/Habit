# Habit 0.2.1 本地备份与界面修复设计

## 目标

Habit 0.2.1 增加可见、可迁移的本地数据备份能力，同时修复 0.2.0 的日期选择器星期标题、Emoji 兴趣分类闪退和 Material 默认紫色渗漏问题。升级必须保留现有 Room 数据库和 DataStore 偏好，不允许破坏性迁移。

## 范围

本次包含：

- 导出和导入版本化 JSON 备份。
- 导入时选择“完全替换”或“合并导入”。
- 设置并显示备份文件夹，默认位置为 `内部存储 / Download / Habit / 数据备份`。
- 更换备份文件夹时自动迁移由 Habit 管理的备份文件。
- 近白淡蓝全局配色，完整覆盖 Material 颜色角色。
- 自有开始日期选择面板，固定显示“一、二、三、四、五、六、日”。
- 修复 Emoji 兴趣分类切换闪退并增加回归测试。

本次不包含：

- 云同步、账号同步或后台管理同步。
- 备份密码和加密。
- 自动定时备份。
- 将 Room 数据库迁移到公共目录。
- 扫描或移动用户在其他目录手工存放的文件。

## 本地数据边界

应用的在线工作数据继续保存在 Android 私有目录：

- Room 数据库：`habit.db`。
- DataStore：主题 ID、最近使用 Emoji、备份文件夹 URI 和偏好更新时间。

公共目录只保存导出的 `.habitbackup.json` 快照。应用始终从私有数据库读取并写入，不直接把公共目录中的 JSON 当作数据库使用。

## 备份格式

根对象采用稳定、版本化结构：

```json
{
  "format": "habit-backup",
  "schemaVersion": 1,
  "appVersion": "0.2.1",
  "exportedAt": 1785686400000,
  "preferencesUpdatedAt": 1785686300000,
  "categories": [],
  "habits": [],
  "checkIns": [],
  "preferences": {
    "themeId": "sky_blue",
    "recentEmojiKeys": []
  }
}
```

日期显示值不进入备份；数据库中的 `createdAt`、`updatedAt` 和 `checkInEpochDay` 原样导出。导入仅接受 `format=habit-backup` 且受支持的 `schemaVersion`，并校验必填字段、ID 引用和时间值。未知字段忽略，以便未来版本向前扩展；未知的更高 schema 版本拒绝导入并提示升级应用。

导出文件名格式为 `Habit-Backup-yyyyMMdd-HHmmss.habitbackup.json`。文件先写入临时文档或临时文件，写完并校验后再公布为最终名称，避免产生半份备份。

## 导出流程

1. 在一致性读取边界内读取分类、习惯和打卡。
2. 读取主题、最近 Emoji 与偏好更新时间。
3. 构造 schema version 1 JSON。
4. 写入当前备份文件夹。
5. 重新读取并校验格式、记录数量和 SHA-256。
6. 显示文件名、保存位置和记录数量。

默认目录在 Android 10 及以上通过 MediaStore Downloads 写入 `Download/Habit/数据备份`。Android 6 至 9 仅在需要时申请公共存储写权限。用户选择自定义文件夹后，通过 Storage Access Framework 保存持久目录授权，后续导出直接写入该目录。

## 导入流程

用户从系统文件选择器选择 `.habitbackup.json` 文件。应用先只读解析和校验，并显示备份时间、版本和各类记录数量，再提供：

- 完全替换：明确提示当前本地数据将被备份内容覆盖，二次确认后执行。
- 合并导入：保留现有数据，冲突时 `updatedAt` 更晚的一方优先。

所有数据库变更在单个 Room 事务中执行。任何解析、约束或写入失败都回滚整个操作。导入成功后刷新工作台、日历、习惯列表和主题。

### 完全替换

按外键顺序清理打卡、习惯和分类，随后按分类、习惯、打卡顺序恢复。备份中的原始 Long ID 可以保留；后续新增记录使用大于当前最大 ID 的值。主题和最近 Emoji 使用备份值。

### 合并导入

- 预置分类按稳定名称匹配。
- 自定义分类优先按“源 ID + createdAt”匹配；无匹配时按规范化名称复用，否则创建新 ID。
- 习惯按“源 ID + createdAt”识别同一逻辑记录。同 ID 但 createdAt 不同视为两个独立习惯，并为导入项分配新 ID。
- 同一逻辑记录冲突时比较 `updatedAt`，较新内容覆盖较旧内容。
- 导入过程维护分类 ID 和习惯 ID 映射，打卡通过映射后的习惯 ID 恢复。
- 打卡按“映射后习惯 ID + checkInEpochDay”去重；冲突时保留 `updatedAt` 较新的记录。
- 主题和最近 Emoji 比较 `preferencesUpdatedAt`；时间较新的一方生效。缺失时间戳视为 0。

## 备份文件夹设置与迁移

“主题与设置”新增“本地数据”卡片：

- 保存位置：显示 `内部存储 / Download / Habit / 数据备份` 或用户选择的目录名称。
- 更改保存位置：打开系统目录选择器。
- 导出数据。
- 导入数据。

更改文件夹后执行安全迁移：

1. 枚举旧目录中由 Habit 命名并可识别的备份文件。
2. 逐个复制到新目录。
3. 对源文件和目标文件进行大小及 SHA-256 校验。
4. 全部复制成功后，才删除旧目录中的对应文件。
5. 任何一步失败时保留旧文件，清理本次未完成的目标副本，并继续使用旧目录。
6. 更新持久目录授权后释放不再使用的旧授权。

若旧目录不可读或授权已失效，应用不猜测路径、不删除文件，提示用户重新授权或仅将新目录用于未来备份。

## 日期选择器修复

不再使用出现中文星期窄标题异常的 Material 3 `DatePicker`。新增项目内日期选择组件：

- 星期标题固定为“一、二、三、四、五、六、日”。
- 周一为每周第一天。
- 支持上月、下月、选中日、取消和确定。
- 内部使用 `LocalDate` 和 epoch day；UTC 毫秒仅在兼容边界出现，不参与显示逻辑。
- 测试覆盖 2026 年 8 月的前导空格、闰年二月和跨年翻页。

## 近白淡蓝配色

默认主题使用以下核心颜色：

- 页面背景：`#FAFCFD`。
- 卡片、弹窗和抽屉：`#FFFFFF`。
- 次级区域：`#F3F7F9`。
- 淡蓝容器：`#EAF4F8`。
- 主强调：`#8EB9CC`。
- 正文：`#263840`。
- 次级文字：`#708087`。

为 `lightColorScheme` 显式设置 primary、secondary、tertiary、surface、surfaceContainer、outline、inverse 和 error 等所有可见角色，禁止任何角色回退到 Material 默认紫色。用户为单个习惯选择的识别色保持不变，仅用于习惯图标和标记。

## Emoji 兴趣分类修复

先通过回归测试复现“新建第一个习惯 → 打开图标选择器 → 兴趣”路径。目录层增加以下不变量：

- 每个可见分类中的 Compose item key 必须唯一。
- 切换分类时 key 包含分类身份，避免前后列表复用冲突。
- 最近列表先规范化并去重。
- 单个异常 Emoji 不能导致整个选择器退出；目录测试覆盖兴趣分类全部选项。

若真实设备堆栈表明根因不是 key 冲突，以堆栈为准修复，不用吞异常代替根因处理。

## 错误处理与用户提示

- 导出失败：显示原因，保留原有备份和当前数据库。
- 文件格式错误：不进入导入确认步骤。
- 版本过新：提示升级 Habit 后再导入。
- 替换或合并失败：事务回滚，显示“未修改现有数据”。
- 文件夹迁移失败：继续使用旧目录，并说明没有删除旧备份。
- 导入和目录迁移期间禁用重复点击。

## 测试与验收

- JSON 编解码、版本校验和非法引用单元测试。
- 替换导入、合并冲突、ID 重映射和事务回滚测试。
- 文件夹迁移的复制、校验、失败保留和授权失效测试。
- 日期网格和中文星期标题测试。
- 所有主题颜色角色不得等于 Material 默认紫色的回归测试。
- Emoji 兴趣分类切换和 key 唯一性测试。
- 全量 JVM 测试、Debug APK 构建和 APK 签名校验。
- 真机验收：导出、改目录迁移、卸载/安装后导入、替换/合并、日期选择和兴趣 Emoji。

## 版本与兼容性

- 版本号更新为 `0.2.1`，versionCode 更新为 3。
- 包名保持 `com.habit.app`。
- 数据库若需新增字段或表，提供显式 Room migration，禁止 `fallbackToDestructiveMigration`。
- 现有 0.1.0/0.2.0 数据在相同签名覆盖安装时原样保留。
- 导入/导出只解决已生成备份后的跨签名迁移；无法从一个不能升级、不能调试且尚未导出备份的旧安装中直接读取私有数据。
